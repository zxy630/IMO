## 项目概述

### 项目背景
Agentv2是一款基于uni-app框架开发的跨平台AI助手应用，主要面向移动端用户提供智能对话服务。项目集成了AI聊天功能、钱包管理、用户认证等模块，旨在为用户提供便捷的AI交互体验和基本的金融管理工具。该项目源于对AI技术在移动应用中应用的探索，结合了聊天机器人与钱包功能的创新融合。

### 建设目标
项目的建设目标包括：
- 提供流畅的AI对话界面，支持文本和图片输入。
- 实现用户钱包余额查询和账单记录展示。
- 支持用户注册、登录和密码找回功能。
- 确保跨平台兼容性，包括微信小程序、App等。
- 提供良好的用户体验，包括侧边栏导航、历史会话管理等。

### 业务价值
Agentv2的应用具有以下业务价值：
- 为用户提供AI驱动的智能助手服务，提升日常生活效率。
- 集成钱包功能，实现AI与金融服务的结合，拓展应用场景。
- 通过跨平台部署，覆盖更广泛的用户群体。
- 提供完整的用户管理体系，支持个性化服务。

### 整体功能范围
项目的主要功能模块包括：
- 用户认证模块：登录、注册、密码找回。
- AI聊天模块：文本对话、图片上传解析、模型切换。
- 钱包模块：余额查询、账单记录展示。
- 个人中心：用户信息管理。
- 历史会话：会话记录查看和切换。

### 技术栈整体说明
项目采用uni-app框架开发，支持Vue.js语法，兼容Vue 2和Vue 3。样式使用SCSS预处理器，UI组件基于uni-ui库。网络请求使用uni.request API，后端接口基于RESTful设计。项目支持热更新和跨平台打包。

## 系统整体架构设计

### 整体分层架构
系统采用前后端分离架构：
- **前端层**：uni-app框架，负责用户界面和交互逻辑。
- **后端层**：提供API服务，包括AI聊天、用户认证、钱包管理等。
- **数据层**：存储用户数据、会话记录、钱包信息等。

### 业务架构
业务架构围绕用户为中心，包括：
- 用户管理：认证、资料管理。
- AI服务：对话处理、模型管理。
- 金融服务：钱包余额、账单管理。
- 会话管理：历史记录、上下文保持。

### 前后端交互架构
前端通过HTTP请求与后端API交互：
- 请求方式：GET、POST等。
- 数据格式：JSON。
- 认证：Bearer Token或X-Username头。
- 错误处理：统一的状态码和错误信息。

### 模块划分
项目模块划分如下：
- 登录注册模块（login.vue, register.vue）。
- 主聊天模块（index.vue）。
- 钱包模块（wallet.vue）。
- 个人中心模块（profile.vue）。
- 关于页面（about.vue）。

### 整体流程逻辑
用户流程：
1. 启动应用，进入登录页面。
2. 登录成功后进入主页面。
3. 在主页面进行AI对话或查看钱包。
4. 可通过侧边栏切换到其他功能。

### 后端接口架构
后端采用RESTful API设计，接口分类如下：

#### 认证接口 (/auth)
- `POST /auth/login` - 用户登录
- `POST /auth/register` - 用户注册  
- `POST /auth/reset-password` - 密码重置
- `POST /auth/security-question` - 获取安全问题

#### 用户功能接口 (/user)
- `POST /user/chat/send` - 发送聊天消息
- `GET /user/chat/threads` - 获取聊天会话列表
- `GET /user/chat/messages/{thread_id}` - 获取会话消息
- `POST /user/profile/update` - 更新用户资料
- `POST /user/profile/change-password` - 修改密码
- `POST /user/bill/parse` - 解析账单图片
- `GET /user/bills` - 获取用户账单
- `POST /user/bill/report` - 生成账单报告

#### 钱包接口 (/api)
- `GET /api/wallet/bills` - 获取钱包账单(分页)

### 接口规范
- **请求方法**：GET(查询), POST(创建/更新)
- **认证方式**：
  - Bearer Token (Authorization头)
  - X-Username头 (备用)
- **内容类型**：application/json (除文件上传外)
- **响应格式**：
  ```json
  {
    "code": 0,           // 0:成功, 1:参数错误, -1:系统错误
    "msg": "操作成功",
    "data": { ... }      // 响应数据
  }
  ```
- **分页参数**：page(页码), page_size(每页数量)
- **错误处理**：统一的错误响应格式

### 数据流转流程
1. **前端请求** → FastAPI路由接收
2. **参数验证** → Pydantic模型校验
3. **业务逻辑** → 服务层处理
4. **数据访问** → ChromaDB集合操作
5. **响应返回** → JSON格式化输出

### 数据持久化策略
- **用户数据**: 永久存储，软删除标记
- **聊天记录**: 永久存储，支持历史查看
- **账单数据**: 永久存储，支持统计分析
- **文件存储**: 本地文件系统 (avatars/, bills/)

### 数据一致性保证
- **事务处理**: ChromaDB原生事务支持
- **软删除**: is_deleted字段标记删除
- **时间戳**: created_at/updated_at自动维护
- **数据验证**: Pydantic模型确保数据完整性

### 缓存策略
- **应用级缓存**: 无 (ChromaDB查询较快)
- **前端缓存**: uni-app本地存储
- **API缓存**: 可选Redis集成 (当前未实现)

### 数据迁移与备份
- **备份**: 定期备份chroma_data目录
- **迁移**: ChromaDB原生导出/导入功能
- **版本控制**: 数据结构随代码版本管理

### 性能优化
- **查询优化**: 使用元数据过滤减少扫描
- **分页加载**: API支持分页查询
- **索引优化**: ChromaDB自动向量索引
- **连接池**: ChromaDB客户端复用
